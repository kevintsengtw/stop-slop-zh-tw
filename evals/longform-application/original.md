# 假想案例：NovaDesk 團隊導入 CodePilot Agent 的十二週實驗

> 驗證聲明：本文為測試 stop-slop-zh-tw 所寫的假想案例，所有公司、產品、人物、數據與網址均為虛構。

## 在浪潮中擁抱變革

在當今這個 AI 飛速發展的時代，軟件開發正在經歷一場前所未有的深刻變革。眾所周知，代碼審查不僅僅是一個找 bug 的環節，更是團隊文化、工程質量與知識沉澱的重要抓手。對於每一位程序員來說，如何透過智能工具提升效率、降低成本、優化體驗，已經成為一個不容忽視的時代命題。

值得注意的是，NovaDesk 並沒有一開始就追求大而全的落地，而是選擇了一條小步快跑、快速復盤的路徑。團隊共有 8 人，包括 5 名後端工程師、2 名前端工程師與 1 名 QA，並於 2026/4/1 至 2026/6/23，在 `support-api` 倉庫進行為期十二週的試點。這不僅是一次工具測試，更是一次研發範式的重新定義。

## 先把邊界講清楚

團隊使用的軟件是 `CodePilot Agent 2.4`，主要對象是 Pull Request。它可以分析代碼變更、生成測試建議、識別接口兼容問題，但默認不能合併 PR，也不能部署到服務器。所有建議都必須由工程師確認，這條規則從試點第一天到最後一天都沒有改變。

模型接口固定走 `https://api.example.test/v1`，日誌保留 30 天，每月預算上限為 NT$3,500。安全小組要求團隊把客戶資料、正式環境密鑰與 `config/production.yml` 排除在輸入範圍之外。可以說，這套配置既兼顧了效率，也守住了安全底線，為後續規模化推廣奠定了堅實基礎。

## 三個階段形成完整閉環

首先，第 1 至第 2 週採取 shadow mode，Agent 只生成建議但不在線上 PR 留言，工程師每天抽查結果。其次，第 3 至第 6 週把 Agent 接到 50% 的 PR，並由原本的 reviewer 決定是否採用建議。最後，第 7 至第 12 週覆蓋全部 PR，但合併權限依然只在人類 reviewer 手上。

透過這種循序漸進的打法，團隊既能控制風險，又能拉齊認知；既能觀察模型的性能，又能沉澱可複用的方法論。整個流程從試運行、收集反饋到全面接入，形成了一個清晰、完整且可持續的閉環。

## 數據告訴我們什麼

試點前的基準來自 2026 年 1 月至 3 月，共 420 個 PR。當時 review 首次回應時間平均為 46 分鐘，正式環境共記錄 17 個缺陷。十二週試點期間共有 398 個 PR，首次回應時間平均降到 28 分鐘，正式環境缺陷為 11 個。

Agent 共提出 1,264 則建議，其中 487 則被採用，採用率為 38.5%；工程師標記 91 則為誤報，占全部建議的 7.2%。模型接口費用合計 NT$3,260，沒有超過每月預算上限。這些數據充分說明，智能代碼審查不僅能顯著提升效率，而且能有效改善質量，真正實現降本增效。

但這裡仍然存在一個需要謹慎理解的限制：試點期間的功能組合與第一季不同，缺陷數量下降可能同時受到需求難度、上線頻率與值班安排影響。現有數據只能說明幾個指標在試點期間一起變化，不能單獨證明是 Agent 造成。這一點至關重要。

## 第五週的意外插曲

然而，真正的轉折發生在第 5 週。Agent 從測試 fixture 讀到一組客戶 email，並把其中 1 個地址複製到 PR 建議。就這樣。警報響了。所有人都停了下來。這不是一個普通的小問題，而是一記重重的警鐘。

安全小組隨即暫停 Agent 2 天，刪除該則建議並檢查日誌。團隊接著新增 DLP 規則、建立 `.agentignore`，也在送出內容前執行 `node scripts/check-agent-input.mjs`。檢查結果顯示，該地址只出現在測試 fixture 與那一則 PR 建議，沒有進入模型訓練資料，也沒有出現在其他日誌。這次事件讓團隊深刻認識到，安全不是一個可以被妥協的選項，而是一條必須被堅守的底線。

## 人沒有被拿掉

試點結束後，8 名成員都填了問卷。6 人希望繼續使用，2 人只願意在生成測試案例時使用，沒有人主張完全停用。QA 李潔的原話是：「它抓得到重複的邊界條件，但不知道哪一個錯誤訊息會讓客服最難回答。」這句話精準地揭示了人機協作的本質。

Agent 擅長掃描大量變更、尋找重複模式、提醒常見遺漏；工程師則理解產品背景、用戶情緒與風險優先級。它不是要取代人，而是要賦能人；不是要削弱判斷，而是要釋放判斷；不是要消滅 reviewer，而是讓 reviewer 把時間花在更有價值的事情上。

## 下一步：從試點走向常態

基於本次試點，NovaDesk 決定再延長 8 週，但範圍仍限制在 `support-api`。每月預算維持 NT$3,500，每週五由 QA、後端與安全小組共同檢查誤報、資料外洩事件與正式環境缺陷。下一階段的成功條件是 review 首次回應時間維持在 30 分鐘以內，且正式環境缺陷不高於第一季的 17 個。

總而言之，CodePilot Agent 的導入是一場意義重大、影響深遠的探索。它標誌著 NovaDesk 從傳統開發走向智能研發，也為團隊打造了新的競爭護城河。未來，隨著算法持續進化、數據不斷沉澱、流程逐步優化，這套模式必將釋放更大的價值。讓我們拭目以待，未來可期！
