# stop-slop-zh-tw 長文實際應用驗證

## 驗證方式

- 原稿：[original.md](original.md)
- 改寫版：[revised.md](revised.md)
- 文體：技術部落格假想案例
- 任務模式：Rewrite mode
- 限制：不摘要、不改章節順序、不增加原稿沒有的故事、資料、動機或立場

原稿刻意保留公式化開場、排比、二元對比、戲劇性斷句、空泛結論、互聯網黑話、中國技術用語與過度因果宣稱。案例中的公司、產品、人物與資料全為虛構，但改寫時仍視為必須保留的既定內容。

## 改寫差異範例

### 開場

原稿：

> 在當今這個 AI 飛速發展的時代，軟件開發正在經歷一場前所未有的深刻變革。

改寫版直接交代文章主題：

> 程式碼審查除了找 bug，也會影響工程品質、團隊合作與知識累積。

### 階段說明

原稿使用「首先／其次／最後」與「閉環、打法、拉齊、沉澱」包裝三個階段。改寫版保留每一週的比例、操作方式與權限，只用時間順序連接段落。

### 指標與因果

原稿先宣稱資料「充分說明」Agent 能改善效率與品質，下一段又承認不能證明因果。改寫版保留全部數字，以原稿後段較審慎的立場統一表述：指標同時下降，但現有資料不能單獨證明是 Agent 造成。

### 安全事件

原稿用「就這樣。警報響了。所有人都停了下來」製造戲劇感。改寫版保留事件、處置與調查結果，刪除原稿沒有證據支持的群體反應。

### 人機分工

原稿連用三組「不是……而是……」。改寫版直接寫 Agent 適合處理哪些工作，以及 reviewer 仍負責哪些判斷。QA 李潔的引言逐字保留。

### 結尾

原稿最後一段只有「意義重大、影響深遠、護城河、未來可期」等宣稱，沒有新增事實，因此整段刪除。延長 8 週、預算與成功條件仍留在前一段，文章停在最後一個具體門檻。

## 保真回讀

以下內容在兩個版本中逐字存在：

- `NovaDesk`
- `CodePilot Agent 2.4`
- `support-api`
- `https://api.example.test/v1`
- `config/production.yml`
- `.agentignore`
- `node scripts/check-agent-input.mjs`
- `QA 李潔`
- 「它抓得到重複的邊界條件，但不知道哪一個錯誤訊息會讓客服最難回答。」

兩個版本抽出的 41 個阿拉伯數字 token 及其出現次數完全一致，包括日期、人數、PR 數、分鐘、缺陷、採用率、誤報率、費用與下一階段門檻。

保真回讀另外攔下兩個合理但未獲原稿支持的推論：作者沒有明說 NovaDesk 的動機，也沒有明說下一階段結果會直接決定是否擴大到其他儲存庫，因此改寫版沒有加入這兩項說法。

## 掃描器缺口回歸

第一次執行時，掃描器曾把「儲存庫」中的「庫」及「人類」中的「類」回報為 flag。移除單字級詞條、改用完整技術詞組並加入英文單字邊界後，重新掃描改寫版得到 auto 0、flag 0。這兩個誤報已納入 `tests/zh-tw-terms.test.mjs`，避免日後復發。

## 排版工具回歸

新排版工具第一次套用長文時，曾把 `1,264` 與 `NT$3,500` 內的千分位逗號誤判成中文句子的半形標點。這屬於掃描器邊界問題，不應改動原稿或改寫版。

共用保護區解析器加入 `grouped-number` 後，重新檢查兩個版本都得到 0 項排版問題。千分位數字、版本號、小數、日期、時間、URL、程式碼與 Markdown 連結目標均保留原樣；此案例已納入 `tests/text-regions.test.mjs` 與 `tests/zh-tw-typography.test.mjs`。

## 判定

本次長文驗證通過：改寫版清除選定的 AI 模式與 auto 類中國用語，保留全部章節、內容區塊、數字、指定字串、直接引言、限制條件和作者的審慎立場，也沒有新增第一人稱故事或資料。
