# 假想案例：NovaDesk 團隊導入 CodePilot Agent 的十二週實驗

> 驗證聲明：本文為測試 stop-slop-zh-tw 所寫的假想案例，所有公司、產品、人物、資料與網址均為虛構。

## 從小範圍試用開始

程式碼審查除了找 bug，也會影響工程品質、團隊合作與知識累積。NovaDesk 用十二週試用記錄審查時間、正式環境缺陷與安全問題。

團隊沒有直接推到所有專案，而是先做小規模試用。8 名成員包括 5 名後端工程師、2 名前端工程師與 1 名 QA；試用期間為 2026/4/1 至 2026/6/23，為期十二週，範圍只有 `support-api` 儲存庫。

## 先把邊界講清楚

團隊使用 `CodePilot Agent 2.4` 處理 Pull Request。它會分析程式碼變更、產生測試建議，也會找介面相容問題；但它不能自行合併 PR，也不能部署到伺服器。所有建議都要由工程師確認，十二週內沒有更改這項規則。

模型固定使用 `https://api.example.test/v1`，紀錄保留 30 天，每月預算上限為 NT$3,500。安全小組要求團隊排除客戶資料、正式環境密鑰與 `config/production.yml`，不把這些內容送進模型。

## 分三個階段接入

第 1 至第 2 週使用 shadow mode。Agent 只產生建議，不在 PR 留言，工程師每天抽查結果。第 3 至第 6 週接到 50% 的 PR，由原本的 reviewer 決定是否採用。第 7 至第 12 週涵蓋全部 PR，合併權限仍只在人類 reviewer 手上。

這種安排讓團隊先觀察輸出，再逐步擴大範圍。每個階段都保留人工審查，也持續收集採用與誤報資料。

## 十二週的結果

基準資料來自 2026 年 1 月至 3 月，共 420 個 PR。當時 review 首次回應時間平均為 46 分鐘，正式環境記錄 17 個缺陷。十二週試用期間共有 398 個 PR，首次回應時間平均為 28 分鐘，正式環境缺陷為 11 個。

Agent 共提出 1,264 則建議，其中 487 則被採用，採用率為 38.5%；工程師把 91 則標成誤報，占全部建議的 7.2%。模型 API 費用合計 NT$3,260，沒有超過每月預算上限。

試用期間，首次回應時間與正式環境缺陷都下降。不過，這段期間的功能組合與第一季不同，需求難度、上線頻率和值班安排也可能影響結果。現有資料只能確認這些指標同時變化，不能單獨證明是 Agent 造成。

## 第五週發生資料外洩

第 5 週，Agent 從測試 fixture 讀到一組客戶 email，並把其中 1 個地址複製到 PR 建議。安全小組發現後，立即暫停 Agent 2 天。

安全小組刪除該則建議並檢查紀錄。團隊新增 DLP 規則與 `.agentignore`，也在送出內容前執行 `node scripts/check-agent-input.mjs`。檢查後確認，該地址只出現在測試 fixture 與那一則 PR 建議，沒有進入模型訓練資料，也沒有出現在其他紀錄。

## Reviewer 仍負責判斷

試用結束後，8 名成員都填了問卷。6 人希望繼續使用，2 人只願意在產生測試案例時使用，沒有人主張完全停用。QA 李潔的原話是：「它抓得到重複的邊界條件，但不知道哪一個錯誤訊息會讓客服最難回答。」

Agent 適合掃描大量變更、尋找重複模式與提醒常見遺漏；工程師仍要判斷產品背景、使用者情緒與風險優先順序。團隊沒有把 reviewer 從流程中拿掉，而是把重複檢查交給 Agent，讓 reviewer 處理需要情境判斷的問題。

## 再延長八週

NovaDesk 決定把試用延長 8 週，範圍仍限於 `support-api`。每月預算維持 NT$3,500；QA、後端與安全小組每週五共同檢查誤報、資料外洩事件與正式環境缺陷。

下一階段有兩個成功條件：review 首次回應時間維持在 30 分鐘以內，正式環境缺陷不高於第一季的 17 個。
